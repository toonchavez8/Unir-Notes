# Actividad: Metodologías y elementos del proceso de diseño UX

## Caso de análisis: Microsoft Learn como referencia para UNIR Dev

## 1. Objetivos

- Desarrollar un trabajo utilizando herramientas y metodologías de diseño de experiencia de usuario.
- Afianzar el aprendizaje de metodologías y elementos del proceso de diseño UX.
- Analizar una plataforma digital real para identificar su brief, arquitectura de información, navegación y elementos base para wireframes.

## 2. Descripción de la actividad

La actividad original plantea el análisis del proyecto **UNIR Dev**, una herramienta de apoyo para profesionistas de TI donde se integran productos y servicios relacionados con desarrollo web y nuevas tendencias tecnológicas.

Debido a que la liga original de UNIR Dev no se encuentra disponible, para efectos de esta actividad se utilizará como referencia funcional la siguiente plataforma:

**Microsoft Learn**  
[https://learn.microsoft.com/es-es/training/](https://learn.microsoft.com/es-es/training/)

Microsoft Learn será utilizada como plataforma de análisis porque presenta características similares al propósito de UNIR Dev: recursos de aprendizaje, rutas formativas, módulos, contenidos tecnológicos, categorías, navegación por temas y materiales dirigidos a estudiantes, desarrolladores y profesionistas de TI.

> [!NOTE]
> Esta referencia no debe copiarse visualmente. Su función es servir como base para analizar cómo una plataforma tecnológica organiza información, guía al usuario y estructura contenidos de aprendizaje.

## 3. Análisis general de Microsoft Learn

Microsoft Learn es una plataforma de aprendizaje tecnológico que organiza contenidos mediante rutas de aprendizaje, módulos, cursos, recursos para estudiantes y rutas profesionales. Su propuesta se centra en permitir que el usuario aprenda a su propio ritmo, explore temas específicos y avance de acuerdo con sus objetivos académicos o profesionales.

Dentro de la plataforma se observan elementos útiles para UNIR Dev:

- **Aprendizaje autodirigido:** el usuario puede avanzar según su disponibilidad y nivel.
- **Rutas de aprendizaje:** los contenidos se agrupan en recorridos guiados.
- **Módulos individuales:** permiten aprender tareas o conceptos concretos.
- **Centro para estudiantes:** agrupa recursos, eventos y oportunidades para alumnos.
- **Rutas profesionales:** conectan el aprendizaje con objetivos laborales.
- **Contenido popular y reciente:** facilita descubrir temas relevantes.
- **Opciones de accesibilidad:** incluye temas claro, oscuro y contraste alto.

## 4. Relación con UNIR Dev

UNIR Dev puede tomar a Microsoft Learn como referencia porque ambos proyectos se relacionan con aprendizaje, tecnología y actualización profesional. Sin embargo, UNIR Dev debe adaptar esa lógica a un ecosistema más amplio, donde además de recursos educativos existan tendencias, herramientas, proveedores y servicios tecnológicos.

La relación principal entre ambas plataformas se puede resumir así:

| Elemento observado en Microsoft Learn | Adaptación propuesta para UNIR Dev |
|---|---|
| Rutas de aprendizaje | Rutas para desarrollo web, IA, nube, datos y ciberseguridad |
| Módulos o cursos | Recursos, guías, tutoriales y herramientas recomendadas |
| Centro para estudiantes | Sección de recursos para estudiantes de UNIR |
| Rutas profesionales | Tendencias y caminos de actualización para profesionistas de TI |
| Contenido popular o reciente | Recomendaciones y tendencias tecnológicas destacadas |
| Búsqueda y navegación por temas | Buscador global, categorías y filtros |

## 5. Públicos principales

- **Estudiantes universitarios:** buscan fortalecer competencias tecnológicas y encontrar materiales confiables.
- **Profesionistas de TI:** buscan actualizarse en desarrollo, nube, inteligencia artificial, datos, ciberseguridad y herramientas digitales.
- **Proveedores tecnológicos:** buscan mostrar productos, servicios o capacitaciones a una audiencia interesada.
- **Usuarios exploradores:** desean consultar rutas de aprendizaje, documentación, cursos o recursos sin tener todavía una necesidad completamente definida.

## 6. Brief propuesto para UNIR Dev

### Nombre del proyecto

**UNIR Dev**

### Descripción general

UNIR Dev es una plataforma digital orientada a estudiantes, profesionistas de TI y proveedores tecnológicos. Su objetivo es centralizar recursos de aprendizaje, tendencias, herramientas, productos y servicios relacionados con desarrollo web y tecnologías emergentes.

### Problema que resuelve

Los usuarios interesados en tecnología suelen encontrar información dispersa en diferentes sitios. Esto dificulta identificar recursos confiables, comparar herramientas, consultar tendencias recientes y encontrar proveedores relevantes.

### Objetivo del producto

Diseñar una experiencia organizada, clara y fácil de navegar que permita buscar, consultar, guardar y comparar recursos tecnológicos, además de conectar usuarios con productos y servicios del sector.

### Público objetivo

- Estudiantes de UNIR interesados en fortalecer conocimientos técnicos.
- Profesionistas de TI que buscan actualizarse o comparar soluciones.
- Proveedores tecnológicos que desean presentar productos o servicios.

### Propuesta de valor

UNIR Dev reúne contenido educativo, tendencias tecnológicas y servicios especializados en un mismo entorno. Su valor principal es reducir la dispersión de información y facilitar que el usuario encuentre recursos útiles mediante categorías, filtros, buscador y recomendaciones.

### Alcance inicial de la plataforma

El alcance inicial contempla una versión funcional con:

- Página de inicio con buscador y categorías destacadas.
- Sección de recursos educativos.
- Rutas de aprendizaje por tema.
- Sección de tendencias tecnológicas.
- Marketplace de productos y servicios.
- Perfil de usuario con favoritos e historial.
- Página de detalle para recursos, cursos, productos o proveedores.
- Formulario de contacto o solicitud de información.

> [!TIP]
> Conviene mantener el alcance inicial controlado. Comunidad, foros avanzados, certificaciones y comparadores complejos pueden quedar para una segunda fase.

### Necesidades principales del usuario

- Encontrar recursos confiables sin revisar demasiados sitios.
- Filtrar contenidos por tema, nivel, tipo de recurso o tecnología.
- Guardar recursos para consultarlos después.
- Comparar herramientas, productos o servicios.
- Descubrir tendencias actuales.
- Contactar proveedores tecnológicos de forma clara.

### Supuestos de diseño

- Los usuarios valoran una navegación simple y categorías comprensibles.
- Los estudiantes necesitan recursos organizados por nivel y tema.
- Los profesionistas de TI prefieren filtros rápidos y contenido aplicable a proyectos reales.
- Los proveedores requieren visibilidad y llamados a la acción claros.
- El contenido tecnológico crecerá con el tiempo, por lo que la arquitectura debe ser escalable.

### Criterios de éxito

- El usuario encuentra un recurso relevante en pocos pasos.
- La arquitectura de información resulta clara para estudiantes, profesionistas y proveedores.
- Los filtros reducen el tiempo de búsqueda.
- Los usuarios pueden guardar recursos y volver a consultarlos.
- Los proveedores cuentan con una ficha clara de presentación y contacto.
- Los wireframes representan las pantallas principales del flujo.

## 8. Rutas de navegación sugeridas

### Ruta 1: estudiante que busca aprender desarrollo web

```text
Inicio
-> Rutas de aprendizaje
-> Desarrollo web
-> Curso o guía recomendada
-> Guardar en favoritos
```

**Resultado esperado:** el estudiante encuentra un recurso claro para iniciar o reforzar conocimientos y lo guarda para consultarlo después.

**Justificación UX:** la ruta parte desde una categoría reconocible y reduce la carga cognitiva al presentar recursos organizados por tema.

### Ruta 2: profesionista que busca actualizarse en inteligencia artificial

```text
Inicio
-> Tendencias
-> Inteligencia artificial
-> Filtro por nivel o tipo de contenido
-> Detalle del recurso
-> Recursos relacionados
```

**Resultado esperado:** el profesionista identifica contenidos aplicables a su trabajo y puede explorar recursos relacionados.

**Justificación UX:** los filtros permiten localizar información útil sin recorrer todo el contenido disponible.

### Ruta 3: proveedor que desea promover un servicio

```text
Inicio
-> Marketplace
-> Proveedores
-> Publicar servicio
-> Vista previa
-> Enviar solicitud
```

**Resultado esperado:** el proveedor puede presentar su oferta a usuarios interesados en tecnología.

**Justificación UX:** separar el marketplace del contenido educativo evita confusión y mantiene clara la intención comercial.
