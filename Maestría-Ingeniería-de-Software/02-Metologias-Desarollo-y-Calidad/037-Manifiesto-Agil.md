- El **Manifiesto Ágil** fue escrito el **12 de febrero de 2001** en **Utah** por expertos en **ingeniería de software** vinculados a métodos como:
    
    - **Extreme Programming (XP)**
        
    - **Scrum**
        
    - **Dynamic Systems Development Method (DSDM)**
        
    - **Crystal**
        
- Su objetivo fue establecer **valores** y **principios** para desarrollar **software de calidad**, de forma **rápida** y adaptable a **requisitos cambiantes**.

---

# **Valores Del Manifiesto Ágil**

- **Valoración de individuos e interacciones**:
    
    - El software lo construyen **personas**.
        
    - El éxito depende del **equipo** y las **relaciones** entre sus miembros.
        
    - Es crucial crear un **entorno de trabajo adecuado** desde el inicio.
        
    - La **comunicación fluida** con el cliente mejora el flujo de información.
        
    - **Procesos y herramientas** son secundarios frente a la **interacción humana**.
        
    - El equipo elige y configura sus **propios procesos y herramientas**.
        
- **Colaboración con el cliente**:
    
    - Las **negociaciones contractuales** suelen generar fricción.
        
    - Cambios de **alcance**, **requisitos** o **plazos** complican el desarrollo.
        
    - El cliente y el equipo deben tener un **objetivo común**: entregar un sistema funcional útil.
        
    - Se deben establecer **canales de comunicación adecuados** y lograr **complicidad** con el cliente.
        
    - El cliente se considera parte del **equipo de desarrollo**.
        
- **Respuesta al cambio**:
    
    - Las **necesidades organizacionales** y el **entorno tecnológico** cambian constantemente.
        
    - El cambio se considera una **ventaja competitiva** y un **valor añadido**.

---

# **12 Principios Del Manifiesto Ágil**

1. **Prioridad**: satisfacer al cliente mediante **entregas útiles frecuentes**.
    
2. **Aceptar cambios de requisitos** en cualquier memento, incluso si el sistema está casi completo.
    
3. Entregar software operativo cada **2 semanas a 2 meses**, como máximo.
    
4. Colaboración **constante y diaria** entre expertos del negocio y desarrolladores.
    
5. Crear un **ambiente positivo** para que el equipo pueda **trabajar con autonomía** y apoyo.
    
6. **Comunicación cara a cara** como el método más eficaz de transmisión de información.
	
7. La medida más relevante vinculada al desarrollo de software **es ver un software que funciona y tiene calidad**.
    
8. Fomentar un **desarrollo sostenible** con ritmo constante durante todo el proyecto.
	
9. Un buen diseño y procurar utilizar las mejores tecnologías en cada proyecto mejorará la agilidad.
	
10. En la agilidad, la simplicidad de las tareas a realizar es fundamenta
	
11. El equipo **se organiza a sí mismo**, sin instrucciones jerárquicas.
	1. El Equipo organiza el proceso que mejor se adapta a su entorno laboral
	2. El equipo ágil organiza la programación del trabajo para que así se obtenga la mejor implementación possible del incremento que se ha de entregar al cliente.
    
12. El equipo de desarrollo ha de set capaz de valorar cómo se podría set más eficaz y actuar en consecuencia para conseguirlo

# **Puntos Adicionales importantes**

- El manifiesto ha sido malinterpretado:
    
    - La **documentación sigue siendo importante** para comprender el sistema.
        
    - La **planificación es esencial**; set flexible no implica **improvisación**.
        
    - Las **reuniones de planificación** deben incluir al cliente.
        
- En el desarrollo ágil:
    
    - El cliente **no es el jefe de proyecto**.
        
    - El equipo de desarrollo se **autogestiona**.
        
- La elección de la metodología depende de:
    
    - El tipo de **organización**.
        
    - La **estabilidad del proyecto**.
        
    - Los **métodos ágiles** son preferibles en entornos **flexibles y cambiantes**.
        
    - Los **métodos formales** son mejores para entornos **rígidos y estables**.
        
    - Existen también métodos **híbridos** o **optimizados** para contextos específicos.

## Micro Test

- ¿Cuál de los siguientes valores establece el manifiesto ágil?
	- Desarrollar software que funciona prima sobre una documentación exhaustiva
- ¿Cuál de los siguientes no es uno de los principios establecidos en el manifiesto ágil?
	- La documentación debe existir en todo memento.
- ¿Cuál es la razón por la cual en el manifiesto ágil se valora más el software funcional que la documentación exhaustiva?
	- Los recursos deben orientarse hacia tareas que verdaderamente aportan valor al proyecto, centradas en el desarrollo del propio sistema.
- ¿Cuál es una mala interpretación del manifiesto ágil?
	- El cliente hará todo el trabajo y adoptará el rol de jefe de proyecto
