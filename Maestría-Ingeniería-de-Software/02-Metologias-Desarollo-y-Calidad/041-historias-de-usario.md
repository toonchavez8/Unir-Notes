# **Historias De Usuario En Desarrollo Ágil**

## ¿Qué Son?

- El término **historia de usuario** proviene del modelo de proceso ágil **XP (Extreme Programming)** y ha sido adoptado por otros marcos ágiles como **Scrum**.
    
- Es **la unidad más pequeña de valor para el negocio** en un desarrollo ágil.
    
- Se utilizan para **recoger los requisitos funcionales** del sistema desde el punto de vista del usuario final.

---

## Características De Las Historias De Usuario

- Siguen un **patrón específico de escritura**.
    
- Se redactan de forma **breve**, comúnmente en tarjetas o post-its.
    
- **No incluyen requisitos no funcionales** (como diseño o rendimiento).
    
- **No especifican cómo se debe implementar** la funcionalidad.
    
- Implican tres elementos clave:
    
    - **Card** (tarjeta): descripción breve.
        
    - **Conversation** (conversación): diálogo con el cliente para detallar.
        
    - **Confirmation** (confirmación): pruebas para validar la historia.

---

## Ejemplos

1. _Como vendedor, quiero registrar los productos y cantidades que me solicita un cliente para crear un pedido de venta._
    
2. _Como supervisor de ventas, quiero consultar un listado de los pedidos registrados y aún no procesados._
    
3. _Como gerente de ventas, quiero consultar pedidos procesados clasificados por vendedor, región y línea de producto._
    
4. _Como analista de logística, quiero enviar un pedido al almacén para su preparación._
    
5. _Como analista de almacén, quiero listar todos los pedidos que debo preparar._
    
6. _Como analista de logística, quiero consultar todos los pedidos listos para despacho._

---

## Buenas Prácticas

- Las historias deben set:
    
    - **Concisas, claras, sin ambigüedades ni contradicciones.**
        
    - Escritas de forma que puedan completarse **en una sola iteración**.
        
- Se puede usar **trazabilidad** para enlazar historias con documentación complementaria.
    
- Se asigna un **identificador único** para referencia y seguimiento.

---

## Diferencias Clave

|Comparación|Historias de Usuario|Casos de Uso|Tareas|
|---|---|---|---|
|Enfoque|¿Qué quiere el cliente?|¿Cómo se implementa en el sistema?|¿Qué trabajo se debe realizar?|
|Nivel de detalle|Bajo|Alto|Muy específico|
|Finalidad|Capturar necesidades del usuario|Analizar comportamiento del sistema|Dividir el trabajo de la historia|

---

## Epopeyas (Epics)

- Son **historias de usuario de mayor tamaño y complejidad**.
    
- Tienen un **objetivo estratégico** y deben **dividirse** en historias de usuario más pequeñas.

### Ejemplo

**Epopeya:**

- _Como usuario, quiero comprar artículos._

**Historias derivadas:**

- Como usuario, quiero seleccionar el artículo.
    
- Como usuario, quiero elegir la cantidad.
    
- Como usuario, quiero seleccionar la forma de pago.
    
- Como usuario, quiero seleccionar la forma de envío.

**Tareas para implementar una historia:**

- Diseño.
    
- Implementación.
    
- Pruebas.
    
- Aceptación.
    
- Demo.
    
- Refactorización.

## MicroTest

- ¿Cuál de las siguientes no es un aspecto que lleva asociado una historia de usuario?
	- La documentacion tecnicas
- ¿Cuál de las siguientes no es una característica de una historia de usuario?
	- Especifica detalles de diseño o requisitos no funcionales.
- ¿Cuál es la diferencia principal entre una historia de usuario y un caso de uso?
	- Los casos de uso ayudan a entender el comportamiento del sistema, mientras que las historias de usuario ayudan a entender qué funcionalidad quiere el cliente.
- ¿Qué se entiende por epopeya en el desarrollo ágil?
	- Una historia de usuario de mayor tamaño y mayor funcionalidad que sigue el mismo formato que una historia de usuario, pero con mayor alcance.
- ¿Qué es una historia de usuario?
	- La unidad mås pequefia possible de valor para el negocio.
